# 使用说明

## 运行前提

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 1809（17763）或更高，x64 |
| .NET 运行时 | 无需单独安装，发布产物自带 |
| SnowLuma | 已在本机启动，且已开启 OneBot 正向 WebSocket |
| 模型接口 | 任意 OpenAI 兼容的 `/chat/completions` 服务（可自建） |

流式聚合不负责登录 QQ，也不发送 QQ 消息。它只作为客户端连接 SnowLuma 提供的 OneBot WebSocket 读取消息。

## 首次配置

### 1. 启动 SnowLuma

打开 SnowLuma，确认它在运行，并在其配置里开启 OneBot 正向 WebSocket，记下**主机、端口和 access token**。默认通常是 `127.0.0.1:3001`。

### 2. 填群白名单

群号在 QQ 群资料页里，不在成员列表里。这一步不能跳——白名单为空意味着不处理任何群。

### 3. 填模型配置

Endpoint 填服务基址（程序自动拼 `/chat/completions`），例如：

- `https://api.openai.com/v1`
- `https://api.deepseek.com/v1`
- `http://127.0.0.1:11434/v1`（本地 Ollama）

API Key 和模型名按服务方要求填。自建服务没有鉴权时 API Key 可留空。

### 4. 点保存

保存后会自动重连，无需重启应用。托盘图标和界面标题会显示当前连接状态。

字段含义和取值范围见[配置说明](configuration.md)。

## 日常使用

应用常驻在系统托盘。关闭窗口只是隐藏，托盘图标仍在，托盘右键菜单里可以：

- 打开主窗口
- 暂停 / 恢复消息处理
- 退出

暂停状态下消息仍然接收和落库，只是不再攒批、不调模型、不发通知——适合你在群里忙别的、不想让摘要打扰的时候。

界面有四个页面：

| 页面 | 内容 |
| --- | --- |
| 消息 | 原始消息流 |
| 摘要 | 按批次组织的摘要、分类和行动项 |
| 待办 | 从摘要里提取的行动项，可标记完成或忽略 |
| 设置 | 见[配置说明](configuration.md) |

摘要分五类：**紧急**（需要立即处理）、**待办**（需要后续行动）、**学习**（知识性、供查阅）、**通知**（公告类）、**普通**。

标为**紧急**的批次会额外弹一条 Windows 通知。程序不主动请求通知权限，Windows 没开的话需要在系统设置里允许这个应用发通知。

## 什么时候该看到东西

正常情况下，从一条消息进来到摘要出现，延迟大致是：

```text
消息到达 → 等窗口攒满（默认 3 分钟）→ 调模型（约 1–5 秒）→ 摘要出现
```

所以刚启动应用时不会立刻有摘要——需要等第一个窗口攒满，或者等某个群刷够 200 条。

**一直没有摘要**，按这个顺序排查：

1. 托盘显示连接成功吗？不是的话先看 SnowLuma 是否在跑、端口和 Token 对不对。
2. 白名单里的群号对吗？在的群确实有发过消息吗？
3. 窗口是不是设得太长了（比如设成了 1440 分钟）？
4. 模型那边通吗？Endpoint、模型名、API Key 有没有写错？

## 消息是怎么被筛掉的

不是每条群消息都会变成摘要。有三道闸：

**白名单**——不在名单里的群直接丢弃，连数据库都不进。

**去重**——1 分钟内内容重复的消息只留一条（群里有人连发刷屏时有用）。

**闲聊过滤**——纯本地规则，不花钱：消息少于 2 个字符算闲聊；符号和表情占比超过 80% 也算闲聊。

含高信号关键词的消息（`@所有人`、`紧急`、`告警`、`故障`、`P0`、`P1` 等）直接豁免闲聊过滤，再短的也会进入分析。

## 模型不可用时

模型超时、返回格式不对、JSON 解析失败——这些都不会让管线停摆。程序会用本地规则生成一份保守摘要兜底，同时把失败原因记进 `llm_calls` 表。

界面上继续有摘要可看，只是质量会降。连接本身也不受影响，恢复后自动接着攒下一批。

## 数据与隐私

所有数据都在本机：

```text
%LOCALAPPDATA%\流式聚合\
├── stream-aggregation.db   消息、摘要、设置、模型调用审计
└── secrets.dat             DPAPI 密文（Token、API Key）
```

- **只读不写 SnowLuma。** 程序不修改 SnowLuma 的任何数据，也不调用它的发送接口。
- **Token 和 API Key 加密保存。** 用 Windows DPAPI 加密，明文不落盘，日志里也不会出现。
- **默认 30 天自动清理。** 可以在设置里改保留天数。
- **消息会发给模型服务。** 这是摘要功能的必要代价——如果群里内容敏感，可以把对应群移出白名单，它们的消息就不会离开本机。

## 卸载

删除 `%LOCALAPPDATA%\流式聚合\` 整个目录即可，不会有残留。

## 常见问题

**改了设置要重启吗？** 不用，保存后自动重连。

**换个 Windows 账户还能用吗？** 程序能用，但凭据要重填。DPAPI 把密文绑在当前用户 + 本机上，拷过去解不开。

**能同时处理多个 QQ 吗？** 目前一次连一个 SnowLuma 实例，也就是一个 QQ 账户。

**会发 QQ 消息吗？** 不会。程序只订阅事件，不发送任何 OneBot API 请求。

**为什么窗口默认 3 分钟？** 短了摘要上下文太碎容易被误解，长了延迟高。3 分钟对通知类群聊比较合适，可以在设置里按群的活跃度调。

**数据库能手动看吗？** 可以，`stream-aggregation.db` 是标准 SQLite，用任意 SQLite 工具都能打开。改之前建议先复制一份。
