# 配置说明

流式聚合没有独立的配置文件。所有设置都在应用界面的**设置页**填写，保存在本机 SQLite 的 `app_settings` 表里；Token 和模型 API Key 例外，它们加密后单独存在 `secrets.dat`。

> **运行环境要求**：需要 .NET 10 Desktop Runtime (x64)，下载地址 https://dotnet.microsoft.com/download/dotnet/10.0 。详见[使用说明](usage.md)的「关于 .NET 运行时」一节。

## 设置项

### SnowLuma 连接

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 主机 | `127.0.0.1` | SnowLuma 所在机器。留空保存会被拒绝。 |
| 端口 | `3001` | 取值范围 1–65535。 |
| Token | 空 | SnowLuma 配置里的 access token，用于 WebSocket 鉴权。 |
| 使用 SSL | 否 | 勾选后用 `wss://` 连接。 |

默认值对应"SnowLuma 和流式聚合在同一台机器上"的常见情况。跨机使用时把主机改成 SnowLuma 的实际地址。

如果 SnowLuma 没开 Token 校验，这里的 Token 可以留空。

### 模型配置

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| Endpoint | 空 | 服务基址，例如 `https://api.openai.com/v1`。 |
| API Key | 空 | 密钥，加密保存。 |
| 模型名 | 空 | 例如 `gpt-4o-mini`、`qwen-plus`。 |
| 超时（秒） | `30` | 单次模型调用的超时，至少 1 秒。 |

**Endpoint 填什么**：填服务基址，程序会自动拼成 `{Endpoint}/chat/completions`。

- 填 `https://api.openai.com/v1` → 请求 `https://api.openai.com/v1/chat/completions`
- 填 `http://127.0.0.1:11434/v1` → 请求 `http://127.0.0.1:11434/v1/chat/completions`
- 直接填完整的 `.../chat/completions` 地址也可以，程序不会重复追加

必须是以 `http` 或 `https` 开头的绝对 URI。协议不对时会在保存后第一次调用时明确报错，错误信息里会指出实际协议是什么。

**超时为什么要单独配**：HttpClient 默认 100 秒对本地小模型太短、对远端接口又太长。这个值直接控制单次调用的等待上限，调大它不会拖慢其他任何环节。

### 群白名单

每行一个群号，也支持用逗号、空格或制表符分隔。留空表示**不处理任何群**。

```text
123456789
987654321
```

保存时会自动去掉首尾空白、空行和重复项。

这是个隐私开关，不只是过滤：不在名单里的群消息连数据库都不会进。填错群号的表现是"连接正常但一直没有摘要"——先确认群号取自群资料页而不是群成员列表。

### 聚合与保留

| 项 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| 窗口（分钟） | `3` | 1–1440 | 攒批时间。窗口越长，摘要越完整但延迟越高。 |
| 保留天数 | `30` | ≥1 | 超过这个天数的消息、摘要、批次和去重记录会在启动时清理。 |

窗口时长直接决定你看到摘要的延迟。想要接近实时就调短，想要更完整的上下文就调长。3 分钟对大多数通知类群聊是个平衡点。

单窗口还有一个 200 条的硬上限（`AggregationOptions.DefaultMaxMessagesPerWindow`），目前不对外暴露。刷屏的群会在到达上限时提前成批——**不会丢消息**，后面的进入下一批。

## 数据存放在哪

```text
%LOCALAPPDATA%\流式聚合\
├── stream-aggregation.db      主数据库（消息、摘要、设置、审计）
├── stream-aggregation.db-wal  WAL 日志
├── stream-aggregation.db-shm  WAL 共享内存索引
└── secrets.dat                DPAPI 密文（Token、API Key）
```

密钥和数据库放在同一个目录是刻意的：它们同属应用数据，分开只会让备份和清理变麻烦。

`secrets.dat` 的内容长这样，全部是密文，看不到原文：

```json
{
  "version": 1,
  "secrets": {
    "onebot.token": "AQAAANCMnd8BFdER...",
    "model.api_key": "AQAAANCMnd8BFdER..."
  }
}
```

几点需要知道的：

- **删掉它等于清空凭据。** 下次启动时 Token 和 API Key 会是空的，需要重新填。设置项（主机、端口、白名单等）不受影响，它们在数据库里。
- **换 Windows 账户后需要重填。** DPAPI 的 CurrentUser 范围把密文绑死在当前用户 + 本机上，拷到别的账户下解不开。
- **坏了不会丢整个应用。** 文件损坏时会被改名成 `secrets.dat.corrupt` 留档，应用以空密钥库正常启动，重新填一次即可。

这个文件只保存在本机工作区，不应上传到公开仓库。

## 改了设置之后

需要重启管线的设置（连接地址、端口、Token、白名单、窗口长度、模型配置）：**保存后自动重连**，不用重启应用。

重连是"先停旧管线、再按新设置起新管线"。新旧管线可能短暂并存——这是刻意的，用界面线程的一次等待来消除重叠并不划算。

仓储、密钥库和模型客户端与设置无关，整个进程内保持复用，不会因为改设置而重建。
